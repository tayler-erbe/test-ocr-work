Leadership briefing · Public benchmark evaluation

Turn difficult PDFs into information people can use.

Local AI can help recover text, tables and evidence from mixed document packets. The evaluation points to different models for different jobs—and a reviewed pilot before operational use.

The recommendation

Start with PaddleOCR-VL-1.6 for financial tables. Trial Nemotron 3.5 Parse for page text, with checks on numbers. Keep people in control of contract and award decisions.

01 / Why this matters

The information exists.
It is difficult to retrieve.

Research proposals, award packets and procurement submissions often combine narrative, scans, budget tables, charts and attachments. Searching or moving this information into a new system becomes manual work when it is flattened into PDFs.

  1. ReceiveBring in the packet and preserve the original.
  2. ReadUse the right tool for text, tables or charts.
  3. ReviewShow proposed values beside their source page.
  4. UseExport approved data for search, reporting or system intake.

This is the proposed application. These document workflows have not been validated end to end in this evaluation. Local processing can keep documents within controlled infrastructure; security still needs implementation and verification.

02 / Which models to use, and why

Choose by task.
There is no single best model.

Budget and financial tables

PaddleOCR-VL-1.6

The strongest confirmed table result in this comparison. It preserved table structure better than the tested 32B vision baseline, without a material numeric-recall loss under the test rule.

First pilot choice
Full-page text

Nemotron 3.5 Parse

Recovered more reference words than the baseline. The numeric test remained inconclusive, so amounts and dates need separate checks. This is a document parser, distinct from Nemotron 3 Nano.

Trial with safeguards
Charts and page layout

Qwen3-VL / DocLayout-YOLO

Retain the task-specific chart routes and layout detector from the earlier evaluation. Extra self-check instructions helped some models and hurt others; use the tested method for each configuration.

Keep tested routes
Contract clauses and field proposals

Qwen3 32B; GPT-OSS 20B as a smaller candidate

These remain candidates for review-assisted proposals. Strict legal scores were modest across the tested models, including Nemotron 3 Nano. None earned approval for unattended legal extraction.

Human review required

Recommendations apply to the tested configurations. They are starting points for a pilot, not a universal ranking. See models, settings and task-level results →

03 / The clearest result

A specialized table model
beat the larger vision baseline.

Table structure similarity

Higher is better · scale 0–1 · 100 financial-report tables / 87 source clusters

PaddleOCR-VL-1.6
0.852
Qwen3-VL 32B
0.763

A confirmed improvement in this test. Both models had the same output-token limit. This measures table structure similarity (TEDS), not the percentage of fully correct tables.

What supports the choice

97.4% numeric recall

PaddleOCR-VL-1.6 recovered most reference numbers. The table recommendation passed the planned improvement and numeric-preservation tests.

Recall does not show that every number is correct or assigned to the right row. Amounts still need validation.

What still needs caution

Better text ≠ trusted numbers

Nemotron Parse improved word overlap, but recovered about 88.2% of reference numbers. The test could not rule out a meaningful numeric loss versus the baseline.

Do not use the page-text result as approval for unattended budget extraction.

Table improvement: +0.090; multiplicity-adjusted 95% interval +0.048 to +0.139. Results use public benchmarks, not a representative sample of research proposals or awards. Read the evidence and limitations →

04 / What is ready

The evaluation is complete.
Production validation is next.

Ready to inform a pilot

Task-specific recommendations, measured results, failure analysis and software checks are available. The next step is a practical prototype that presents source-linked proposals for review.

Not yet established

Accuracy on the actual business documents, sustained throughput on the target server, reviewer workload, operating cost and production security have not been demonstrated.

Deployment planning targets one NVIDIA L4 (24 GB) or L40S (48 GB). Round 3 was measured on an RTX 5090; target-server speed and memory headroom must be tested before rollout. This evidence alone does not justify a hardware purchase.

Fine-tuning may help once representative labels exist. It was not tested here and cannot be assumed to fix missing OCR text or poor retrieval.

05 / The next decision

Approve a bounded pilot,
not an automated rollout.

  1. Agree on the useful output.

    Which fields matter, where do the documents come from, and should approved data feed search, a spreadsheet or an enterprise system?

  2. Build a representative review set.

    A small convenience sample is not enough to establish readiness. Plan an initial set of about 100 representative documents, with difficult scans, tables and missing fields included. Have two reviewers independently label a subset; confirm the final sample size against the acceptance targets.

  3. Test the recommended routes on the real workflow.

    Measure field correctness, numeric preservation, source traceability, processing time and human correction effort on the target server.

  4. Decide whether to scale or adapt.

    Set acceptance thresholds before scoring. Improve retrieval, prompts or training only where the measured errors justify it, and confirm changes on untouched documents.

The leadership ask

Identify a workflow owner, a domain reviewer and an approved document source. Agree on the first fields and success criteria. Use the pilot evidence to decide the next investment.
